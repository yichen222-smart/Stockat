# Stockat 股小喵｜管理员指南

版本：1.0｜参考运行环境：Linux 2C2G｜时区：Asia/Shanghai

> 管理员负责用户准入和运行检查，不需要手动维护服务器配置。遇到新增用户、二维码或早报故障时，直接在本项目的 Codex 对话中说明目标即可。

## 1. 管理员职责和边界

管理员拥有普通用户的全部功能，并可以：

- 生成一次性业务邀请码；
- 查看用户列表；
- 停用、启用或软删除普通用户；
- 查看微信中的简要系统状态；
- 让 Codex 检查服务器、定时器、数据源、备份和独立网关；
- 让 Codex 为新用户生成全新的微信二维码。

管理员默认不能查看普通用户的具体关注、成交记录和个性化报告。不要为了排障要求复制用户隐私数据。

## 2. 新增用户：一句话入口

在本项目的 Codex 对话中直接说：

`我要加新用户`

Codex 会自动读取《新增用户入口》，调用服务器向导并完成以下工作：

1. 检查服务器和已有网关；
2. 自动选择下一个用户编号；
3. 新建独立 `HERMES_HOME`；
4. 复用 AI 服务配置，但绝不复制旧用户微信令牌；
5. 生成最新的 ClawBot/iLink 微信二维码；
6. 完成短期配对码批准；
7. 启动独立 systemd 网关并设置开机自启；
8. 验证业务用户和独立发送路由。

Codex只会在必须本人完成的动作上暂停，而且一次只要求一个动作。

### 2.1 实际加入顺序

1. 管理员对 Codex 说：`我要加新用户`
2. Codex准备好隔离网关后，会让你通知新用户打开微信；你回复：`现在`
3. 新用户立即扫描 Codex 刚生成的二维码并在微信中确认；
4. 新用户收到 8 位短期配对码后，把该码告诉 Codex；
5. Codex批准配对并确认新网关运行；
6. 管理员在自己的微信机器人中发送：`添加用户`
7. 把机器人返回的 `XXXX-XXXX` 一次性邀请码交给目标用户；
8. 新用户在自己的机器人会话发送：`加入 XXXX-XXXX`
9. 新用户收到欢迎初始化消息后，加入完成。

二维码可能很快过期。过期时只需对 Codex 说：`二维码过期了，请刷新`。Codex会继续当前任务并展示最新二维码，不会创建重复网关。

### 2.2 为什么需要两种码

- 二维码：把新的 ClawBot/iLink 身份连接到独立 Hermes 网关；
- 8 位配对码：批准该微信用户访问这个 Hermes 网关；
- `XXXX-XXXX` 邀请码：把微信用户加入盘前助手的业务数据库。

三者用途不同，均为短期材料。不要保存为长期密码，也不要在群聊中传播。

## 3. 管理员微信指令

| 你想做什么 | 发送内容 | 说明 |
|---|---|---|
| 生成业务邀请码 | `添加用户` | 15 分钟有效、只能使用一次 |
| 查看用户 | `查看用户列表` | 返回 8 位用户编号、名称、角色和状态 |
| 停用用户 | `停用用户：1234abcd` | 用户不能继续使用，数据保留 |
| 启用用户 | `启用用户：1234abcd` | 恢复正常使用 |
| 软删除用户 | `删除用户：1234abcd` | 从正常列表移除，历史数据保留 |
| 查看简要状态 | `查看系统状态` | 查看微信、Hermes、SQLite基本状态 |

用户编号以 `查看用户列表` 返回的 8 位编号为准。不要使用微信昵称代替编号。

删除属于管理操作。发送前先核对编号；当前实现为软删除，不会立即物理清空数据库。

## 4. 早间自动发送机制

每日自动发送时间线：

| 时间 | 系统动作 |
|---|---|
| 08:05 | 首次启动，检查交易日和用户设置；交易日继续准备行情与新闻 |
| 08:30起 | 交易日按用户串行发送三个报告栏目；非交易日发送一条固定休市互动提醒 |
| 08:40 | 对未成功用户自动补跑，不重发已完成用户 |
| 09:00 | 最后一次同日补跑 |
| 09:15 | 盘前窗口截止；此后不再把旧内容当作盘前消息补发 |

可靠性规则：

- 一个用户的微信网关故障，不会阻止其他用户生成和发送；
- 没有独立发送路由的用户会失败关闭，不会退回管理员网关；
- 每个报告栏目单独记录发送状态；第二条失败时，重试从第二条继续；
- 已完成用户在同日补跑中会被跳过；
- 交易日历获取失败且没有本地缓存时，系统停止发送，避免法定休市日误发；
- 所有非交易日（含周末和法定休市日）只发送固定休市互动提醒，不采集或发送行情、新闻和网格参数；
- 非交易日提醒与交易日报告共用逐用户状态，补跑不会重发已经成功的用户。

极少数情况下，如果微信接口已经收到了消息，但服务器在写入“已发送”状态前瞬间断电，仍可能出现一条重复消息。这是外部微信接口不提供端到端幂等编号时无法完全消除的窄窗口。

## 5. 管理员如何与 Codex 沟通

建议直接说结果目标，不需要复制服务器命令：

- `我要加新用户`
- `二维码过期了，请刷新`
- `检查明天早报定时器是否正常，不要发送测试消息`
- `检查今天谁没有收到早报，只给我汇总状态，不读取用户内容`
- `检查某个用户的独立微信网关，不要重启其他用户`
- `检查最近一次备份是否可恢复`
- `先备份，再部署当前交付版本，并验证定时器`

如果 Codex 要求扫码，它应一次只要求一个动作。不要把 API Key、服务器密码、SSH 私钥或微信令牌发进对话。

## 6. 日常检查

管理员平时只需确认：

1. 交易日是否正常收到早报；
2. 普通用户是否能使用“查看我的关注”；
3. 微信中的 `查看系统状态` 是否正常；
4. 新用户加入后是否收到欢迎初始化消息。

每周或出现异常时，可以让 Codex只读检查：

- 晨报 timer 的下一次触发；
- 所有独立微信网关是否 active；
- 最近一次早报成功、失败数量；
- RSSHub、AKShare、TA-Lib 和 SQLite；
- 磁盘、内存、swap和最近备份。

## 7. 故障处理

### 所有人都没收到早报

让 Codex检查主定时器、交易日历、服务器网络和应用服务。不要先手动重复触发多次。

### 只有一个用户没收到

优先检查该用户的独立网关和 delivery route。其他用户正常说明公共行情和新闻阶段大概率已经完成。

### 二维码一直过期

让新用户先停留在微信扫一扫界面，再对 Codex说“现在”。只扫描当前对话刚显示的二维码；旧图片不要继续尝试。

### 微信提示配对码

把该 8 位短期配对码告诉 Codex即可。不要把长期微信令牌或服务器环境文件发出来。

### 报告数据异常

先核对“数据截至日期”和前复权口径。若行情源失效，系统应停止相关网格而不是编造价格。

## 8. 备份和恢复

系统每天 03:30 自动备份 SQLite、配置、技能和部署状态。恢复数据库、修改定时器、关闭全部早报或物理删除用户都属于高风险操作，应先让 Codex创建额外备份并明确恢复点。

不要手工删除 `/opt/grid-assistant/data`、`/opt/grid-assistant/backups` 或任何 `hermes-*` 目录。

## 9. 安全与投资边界

- 不在微信、截图、文档或工单中传播 API Key、服务器密码和微信令牌；
- 每位用户必须使用自己的独立网关，不能复制其他用户凭据；
- 邀请码只交给目标用户，不发到群聊；
- 不把 RSSHub、SQLite 或管理端口暴露到公网；
- 本助手不连接券商、不自动交易、不读取资金和持仓，也不承诺收益；
- 所有输出只作信息整理和参数参考，不构成投资建议。
